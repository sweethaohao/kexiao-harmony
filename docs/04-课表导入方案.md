# 课晓 · 课表导入方案

> 版本：v0.1（草案）｜ 已用真实课表验证 ✅

## 1. 为什么放在电脑侧解析？

教务系统导出的课表是 **Word (.docx)**。在鸿蒙 App 内解析 docx 需要：解压 zip + 解析 XML + 处理复杂表格 —— 工作量大、易踩坑、难测试。

因此采用**"电脑侧转换 + App 导入 JSON"**方案：
- 转换脚本：`tools/parse_schedule.py`（Python，**仅标准库**，零依赖）
- 产物：结构化 JSON
- App：只负责读 JSON → 存数据库 → 展示

> 好处：解析逻辑可独立测试（已完成）、便于写博客、App 端保持轻量。

## 2. 课表真实结构（实测）

教务导出的表格：

```
列:  [0] 时间段(上午/下午/晚上, 竖合并)
     [1] 节次(第一节..第十三节)
     [2..8] 星期一 星期二 星期三 星期四 星期五 星期六 星期日
```

每个单元格内，**一门课由若干独立段落 `<w:p>` 组成**，典型 4 段：

```
P0: 课程名            例如 "大学英语（3）"（可能含全角括号）
P1: 课程号            例如 "EN2003"（独立成段）
P2: (周次) (节次) 校区 教室  教师    例如 "(1~3,5~12周) (第三节-第四节) 主校区 B203  李慧"
P3: 上课班级列表      例如 "B2401（1班）;B2402（1班）"（忽略）
```

**同一格可含多门课**（4 段一组重复），例如星期一第一节同时有：
- 微积分（上）（1~12周）
- 计算机导论实验（13~16周）

## 3. 解析算法

1. **读表**：`zipfile` 打开 docx，解析 `word/document.xml`，取第一个 `<w:tbl>`。
2. **单元格转文本**：单元格内按 `<w:p>` 段落，用 `\n` 连接（关键！保留段落边界）。
3. **定位列**：找含"星期一"的表头行；正文星期列 = 表头星期序号 + 2（跳过分组列、节次列）。
4. **逐格解析**（`parse_cell_paras`）：
   - 扫描段落；**遇到纯数字段（课号）** → 前一段是**课程名**；
   - 其后 1~3 段内找 `(周次)(节次)` 元信息段；
   - 组合成一门课；`P3` 班级段忽略。
5. **周次解析**（`parse_weeks`）：支持 `1~12周`、`1~3,5~12周`、`4周`、`1,3,5周`。
6. **去重 + 排序**：按 (课程名,课号,星期,节次,周次,教室) 去重；按星期、节次排序。

## 4. 用法

```bash
cd tools
# 输出建议放在工程外：真实课表不要提交进 Git，更不要放进 resources/rawfile/
python3 parse_schedule.py "我的课表.docx" -o ../../data/schedule.json
```

输出示例：

```
解析完成: 12 条课程记录 -> ../../data/schedule.json

  星期一 第1-2节 计算机导论实验   周次=[13,14,15,16]  教室=主校区 实验楼 3-301  刘阳
  星期一 第1-2节 微积分（上）     周次=[1..12]        教室=主校区 A101  张明
  ...
```

## 5. 验证结果（示例课表）

| 场景 | 结果 |
|---|---|
| 连续周次 `1~12周` | ✅ |
| **并集周次** `1~3,5~12周` → `[1,2,3,5..12]` | ✅ |
| 单周 `4周` / `1周` | ✅ |
| 单格多课（微积分 + 计算机导论实验同格） | ✅ |
| 跨节次 `第1-2节` | ✅ |
| 课程名含全角括号 `大学英语（3）` | ✅ |
| 场地名教室（体育：主校区 体育馆） | ✅ |
| 合计 | **12 条全部正确** |
