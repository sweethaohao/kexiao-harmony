# 课晓 · 课表导入方案

> 版本：v0.5
>
> **主路径已换**：对「禁选中 + 反调试 + 打印窗口也废」的教务系统，
> 唯一零门槛的通路是 **教务处官网公开的 `.xlsx` → App 内选班导入**（§7.1，已实现并实机验证）。
> 粘贴导入 / HTML 风味 / 手动添加都保留，对其它学校仍然有效。
>
> **明确不做**：PDF 解析（§3.6 论证过，成本极高而拿到的信息量与粘贴纯文本无异）。

## 1. 先说说走过的弯路

最早的设计是：**教务系统导出 Word → 在电脑上跑 Python 脚本 → 转成课晓的 JSON → 应用导入**。

这条路技术上跑通过，示例课表 12 条记录全部解析正确。但它**推广不了**，原因有四条：

| 问题 | 说明 |
|---|---|
| 要有一台电脑 | 目标用户是学生，手上多半只有手机或平板 |
| 要会跑脚本 | 命令行、Python 环境，普通学生不会 |
| Word 格式因校而异 | 换一所学校，脚本里的表格结构假设就全错了，没法做成通用工具 |
| 说不清为什么这么绕 | 让用户"先导出再转换再导入"，解释成本比收益还高 |

**结论：这条路只能当"开发者自己用的工具"，不能当产品功能。** 于是它被降级放进了 `tools/advanced/`（见文末）。

## 2. 看看市面上的课表 App 怎么做

### 2.1 换个问法：数据在「哪一侧」被取出来

表面上各家的导入方式五花八门，但真正决定成本和风险的只有一个问题：
**「把教务系统变成本地数据」这件事，是在谁的地盘上做的？**

```
                                       适配维护   隐私风险   用户门槛
① App 内    App 内置 WebView 打开教务 ── 极高 ──── 高 ────── 低
② 用户浏览器 脚本/另存为/查看源码      ── 低 ───── 无 ────── 高
③ 另一个用户 分享码、二维码            ── 无 ───── 无 ────── 极低
```

- **① App 内**：WakeUp（自称适配 1800~3000+ 校）、超级课程表、轻屿课表。
  体验最好（输个学号就行），但适配量是**乘法级**的负担：每所学校、每次教务改版都要重来。
  更要命的是要用户交出教务系统账号密码 —— 这是市面上被诟病最多的一点，
  也是个人项目**绝对不能碰**的红线。
- **② 用户浏览器**：数据在用户自己机器上、用户自己登录的页面里被取出，App 只负责
  **读文件 / 读文本**。典型实现：
  - WakeUp 的「从 HTML 文件导入」：在课表区域右键 → 查看源代码 → 找课程名 → 全选复制 → 存成 UTF-8 文本 → App 里选学校类型导入
  - WakeUp 的「树维教务简易导入」：网页上点一个按钮 → 自动下载 HTML → 发给手机 → 导入
  - 油猴脚本派：[`WanderLandWalker/SCUT_Lesson_Table`](https://github.com/WanderLandWalker/SCUT_Lesson_Table)（华南理工，支持 JSON/CSV/ICS/XLSX 等 9 种格式导出，直接拦 AJAX 拿接口 JSON）、[`Jiale23/ConvertIcs-Script`](https://github.com/Jiale23/ConvertIcs-Script)（正方 → ICS）、[`huangyi718/coursedate`](https://github.com/huangyi718/coursedate)（导出 CSV）
  - [`JFyuhong/JLU_schedule`](https://github.com/JFyuhong/JLU_schedule)（吉林大学）的 iOS PWA 版做的正是这条路：**Safari 一键书签导入**
- **③ 另一个用户**：WakeUp 的「分享口令」、轻屿课表的二维码传输。
  **一个人折腾，全班受益** —— 同一个教学班的课表本来就基本一样。

### 2.2 顺带说说「小爱课程表」那一派

用户最早印象里"有课表软件让用户用开发者工具扒教务系统"，指的应该就是
**小米的小爱课程表**：

- 官方提供 **AISchedule DevTools**（一个 Chrome 扩展），开发者在里面为**自己学校**写三个 JS：
  | 文件 | 职责 |
  |---|---|
  | `provider.js` | 怎么拿到数据（抓页面 HTML，或直接调教务接口） |
  | `parser.js` | 把 HTML / JSON 解析成统一结构 |
  | `timer.js` | 作息时间表 |
- 社区适配集合：[`kqakqakqa/xiaoai-schedule-parser`](https://github.com/kqakqakqa/xiaoai-schedule-parser)（30+ 校，按教务系统分类：新正方 V9.0 / 旧正方 / 起迪）
- 教程生态：`aisc.ioll.top`、`open-schedule-prod.ai.xiaomi.com/docs`

**但要说清楚一件事**：那套开发者工具是给**适配者（写规则的人）**用的，
不是给普通用户的导入方式。普通用户在小爱 App 里选学校就完事了，
真正跑的是适配者写好的 `parser`。

所以它的价值对我们来说是：**「一家学校一个解析规则」这个模式值得借鉴**，
而不是「可以把那套代码搬进来」。何况它是 JS，进不了 ArkTS 工程。

### 2.3 传统对比表

| 方式 | 代表 | 用户门槛 | 我们的维护成本 | 结论 |
|---|---|---|---|---|
| 教务系统一键抓取 | WakeUp、超级课程表 | 输学号密码 | 极高（要适配 3000+ 所学校） | **不做**（隐私红线 + 个人项目扛不住） |
| 分享码 / 口令 | WakeUp、超级课程表 | 粘贴一串码 | 中 | **高性价比，做**（见 §11） |
| 用户侧脚本 | 小爱 AISchedule、SCUT、JLU | 高（要装扩展/会开控制台） | **低** | 做，但只放在 GitHub，不进 App |
| HTML 文件导入 | WakeUp | 中（查看源码 → 存文件） | 中（按教务类型写通用规则） | 做（见 §7） |
| Excel / CSV 文件 | WakeUp、柠檬课程表 | 下载模板、填表 | 低 | 可做 |
| 截图 OCR | WakeUp | 截图即可 | 中高，且要逐项校对 | 收益对不起成本，暂不做 |
| 手动添加 | 所有 | 逐条录入 | 极低 | **必做**（兜底 + 纠错手段） |
| **粘贴文本** | —— | **全选复制** | 中（要写解析器） | 主入口，**但对部分学校不适用（见 §3.4）** |

## 3. 关键洞察：粘贴能一次吃下两种情况

在教务系统的课表页面上 `Ctrl+A` / `Ctrl+C`，或者在 Excel 里把课表区域选中复制 ——
剪贴板里都能拿到**「制表符分列 + 换行分行」的纯文本**。

也就是说「粘贴」这一个入口同时覆盖了网页和 Excel 两种来源，而且：

- 不需要电脑
- 不需要跑脚本
- 不需要下载模板填表

这是投入产出比最高的一条路。

### 3.1 ⚠️ 但有些教务系统，纯文本里连"格子"都没有

后来拿用户自己学校的课表实测，发现上面这句话**说得太乐观了**。

应用内给剪贴板读出来的内容打了个形状点（只记行数/制表符数，不记内容）：

```
clipboard flavor: types=text/plain  plain=4594
paste shape:      chars=4594  lines=275  tabLines=16  tabs=21
```

4594 字、275 行的一整张课表，**制表符一共只有 21 个**：

- 6 个在表头行里（`星期一⇥星期二⇥…⇥星期日`）；
- 15 个在节次行标的末尾（`第一节⇥`、`第三节⇥`… 唯独 `第二节` 没有）。

**格子与格子之间，一个分隔符都没有。** 原始形态长这样（每门课固定四行）：

```
星期一⇥星期二⇥星期三⇥星期四⇥星期五⇥星期六⇥星期日
第一节⇥
离散数学
12750
(1~12周) (第一节-第二节) 金海 4309  阙程晟
f250117（卓越班）;f250118（卓越班）
数字电路综合实验
12757
(13~16周) (第一节-第二节) 金海 12-713  蒋宙杰
…
第二节
第三节⇥
…
```

看出来了吗：**每门课自带课程名、课程号、周次、节次、校区、教室、教师 —— 唯独没有"星期"。**
而"星期"是靠它在表格里的**列位置**表达的，列位置一旦丢了，纯文本怎么推都推不回来。

> 这一条很反直觉：文本里信息看着很全，用户盯着自己的课表左看右看，
> 完全想不明白为什么程序会认不出来。

### 3.2 解法：剪贴板里其实还有第二份数据

网页上复制的表格，剪贴板里**同时躺着两种"风味"**：

| 风味 | 内容 | 还用得了吗 |
|---|---|---|
| `text/plain` | 只剩换行，格子结构丢失 | 上面那种教务系统认不出 |
| `text/html` | 真正的 `<table>`，行=节次、列=星期 | ✅ 结构完好，一格不差 |

所以读剪贴板时**优先拿 HTML**，把它摊平成"制表符分列 + 换行分行"的文本，
再交给**同一套**解析规则（`service/HtmlTableService.ets`）——
这样不必为 HTML 另写一份业务规则，也就不会出现"两条路各说各话"。

摊平过程中几个必须处理的细节：

| 细节 | 不处理会怎样 |
|---|---|
| **展开 `rowspan` / `colspan`** | 课表里跨节次的课用 `rowspan=2`，不展开第二行会少一格，**后面整排列位置全体左移，星期全错** |
| **`<br>` 换成 `\n` 而不是删掉** | 格子里的课程名/周次/教室会粘成一坨，认不出来 |
| **剥掉 CF_HTML 包头** | Windows 剪贴板的 HTML 风味外面包着 `Version:0.9 … <!--StartFragment--> …` |
| **解实体转义** | 课程名里会冒出 `&amp;`、`&nbsp;` |

对应地，输入框里手动 `Ctrl+V` 是拿不到 HTML 的（普通文本框只给纯文本），
所以界面上要引导用户点左下角的「粘贴」—— 那是 `PasteButton` 安全组件，
点一下能拿到两种风味。

### 3.3 认不出来时，要把原因说清楚

用户看到的是自己的课表，程序却认不出来 —— 这时候一句"格式不正确"毫无帮助。
所以专门做了一个 `diagnoseFailure()`：认出上面那种"课块流"就直说：

> 这段内容应该是课表，但复制出来的**纯文本里"星期"这一列不见了** ——
> 格子之间连分隔符都没有，没法判断哪门课是周几。
> 办法：回到课表页面，在表格上 Ctrl+A 全选、Ctrl+C 复制，然后点本页左下角的「粘贴」。
> 应用会连剪贴板里的表格结构一起读，星期就不会丢。

**宁可明确失败，也不要按顺序硬猜一个"星期一、星期二……"** ——
猜错了数据看着像对的，星期全错，用户还查不出来。

### 3.4 ⚠️⚠️ 有些教务系统，连"选中"这一步都不给你

再往后实测，又撞上一堵墙：用户学校的教务系统**按 `Ctrl+A` 什么都没选中**，
鼠标拖也拖不出选区。也就是说 **§3.2 那个「读剪贴板 HTML 风味」的解法，在这所学校同样是死的** ——
不是取不到 HTML，而是用户根本没有机会把表格放进剪贴板。

顺带一提，该校还：

- 拦截 `F12`
- 检测到开发者工具打开就执行 `debugger` 把页面挂起

**但这里有个关键判断：这些都只作用在「交互层」。**

| 手段 | 拦的是什么 | 拦不住什么 |
|---|---|---|
| CSS `user-select: none` | 鼠标划选、`Ctrl+A` | 脚本直接读 DOM |
| JS 拦 `copy` / `selectstart` / `contextmenu` | 右键菜单、复制事件 | 脚本直接读 DOM |
| 拦 `F12` 键 | 键盘打开开发者工具 | 菜单/快捷键的其它入口、浏览器扩展 |
| `debugger` 反调试 | 页面被人肉调试 | 浏览器扩展/书签小工具（**它们不打开开发者工具**） |

浏览器最终**必须把内容渲染出来**，数据就一定在 DOM 里。所以只要换一条
**不经过「选中 → 复制」** 的通道就行：

```
页面 DOM  ──►  用户侧脚本直接读  ──►  生成文件/文本  ──►  课晓「从文件导入」
```

配套工具已经写好：**`tools/advanced/kexiao-export.js`**（浏览器 Console 脚本）
+ `tools/advanced/README.md`（含反调试 `debugger` 的处理办法）。

> **红线**：只处理用户**自己登录后能看到的那一页**。不做自动登录、不代填账号密码、
> 不批量抓取学校服务器。越过这三条，性质就变了。

### 3.5 ★ 换个思路：先找一条「根本不经过教务系统」的数据来源

把事情想透一层就会发现：我们真正要的是**课表数据**，不是**教务系统**。
之所以一直在和教务系统的反复制机制死磕，是因为默认了"数据只能从那个页面拿"。
其实不然。实测下来有更省事的路，按**门槛从低到高**排：

| | 路子 | 门槛 | 实测结论 |
|---|---|---|---|
| ① | 教务系统自带的「打印」窗口 | 点一下 | ❌ **本校实测走不通** —— 打印预览里也 `Ctrl+A` 不到，手动拖选复制出来**同样没有制表符**（详见 §3.6） |
| ② | 教务系统自带的「导出 Excel」 | 点一下 | ⭕ 有就一定好使：导出的就是结构完整的表格文件，比复制文本干净 |
| ③ | **教务处官网公开的课表文件** | 下载一个文件 | ✅ **最优解。已实现进 App 并实机验证**（详见下） |
| ④ | 浏览器「查看网页源代码」(`Ctrl+U`) | 会 `Ctrl+F` | ⭕ 搜得到课名 → 说明是服务端渲染，源码里就是完整表格 |

#### ③ 教务处官网的公开课表文件（本文件记录的重点发现）

很多学校的**教务处官网**每学期会挂出「各校区课表 / 各教学班课表」的 `.xlsx` 附件。
这份文件：

- 是**教务系统自己打印导出的**，结构完整 —— 星期是独立的列，节次是独立的行
- 是**公开发布的**，和教务系统的登录态、反复制机制**完全没有关系**
- 精度上覆盖"排课计划"这一层（临时调课不一定同步）

**实测（作者本校，2026-10-15）**：把这份 xlsx 里作者所在小班（`f250117` 卓越班，
35 人）的那一块抽出来，得到一个 21 格 / 27 门课的课表，13 门课的教师名与
教务系统网页上看到的**逐个吻合**（赵厚宝、张文英、王悦纯、孔楠、阙程晟、方雪晴、
范国强…）。也就是说：**这条路拿到的数据，质量不比教务系统页面差。**

#### 这个格式的两个特征（解析器专门为它改过）

教务系统的「班级课表打印」格式有两个独有的写法，凑在一起极容易把
「一整格」误判成「一门课」，让课名串上别人的教室和老师：

1. **同一格放多门课，之间用一整行 `-----------` 隔开**

   ```
   离散数学
   1-12
   -----------
   数字电路综合实验
   13-16
   ```
   → 这种分隔线是**显式**信号，比任何启发式都可靠，优先按它切（`isGroupSeparator`）

2. **周次写成光秃秃的 `1-12`**（列标题已说明是周次，所以不写「周」字）
   → 拆格时不能再要求"必须含「周」字"，否则同格多课全被压成一门（`weekLike`）

**修复前实测**：27 门课只解析出 22 门，**教室和教师全部错位**（离散数学串上了
数字电路综合实验的教室 `12-713` 和教师 `蒋宙杰`）。修复后 27 门全对。

#### 附：这个格式里"跨节次"是怎么表达的

xlsx 的课表网格有 `第一节 ~ 第十三节` 十三行，但课只落在**奇数行**上
（`第一节 / 第三节 / 第五节 / 第七节 / 第九节`），占 2 行 —— 因为源单元格是
纵向合并的（`rowspan=2`），合并后内容落在顶行，下一行留空。

于是有一条**很干净的推断规则**：

> 一门课占的节次范围 = 从它所在的行开始，一直到**同一列下一个有内容的行之前**。

这条规则不需要任何显式标注，也天然支持"跨 4 节"的课（实测有 `第五节-第八节` 的
数字电路综合实验）。转 xlsx/打印格式时应当用它，而不是直接用行标签。

### 3.6 ⚠️ 实测：「打印窗口」在同一个学校也走不通（附：为什么不用 PDF）

§3.5 的 ① 是理论上最省事的一条，但在**本校实测失败**，如实记下来免得后人再试一遍：

> 打印预览窗口里**也 `Ctrl+A` 不了**，只能手动拖选；但手动选中后 `Ctrl+C`，
> 复制出来的文本**仍然不含制表符**。

也就是说和主页面是同一个病：拿到的还是一串没有分隔符的「课块流」，
星期列照样丢（参 §3.1）。

原因是打印样式下表格的列结构对"选区→剪贴板"这条通道同样是不可见的 ——
打印预览是独立页面没错，但**"独立页面"只保证反复制的脚本没跟过来，
不保证选区里会带表格结构**。这两件事被混为一谈过，实测把它分开了。

#### 那 PDF 呢？

**不推荐做，也不值得做。** 两个层面：

1. **成本层面**：PDF 里文字只带坐标，没有"表"的概念。要从 PDF 还原表格，
   得解 xref 表 → 解 FlateDecode 压缩流 → 解析 content stream 的
   `Tj/TJ/Td/Tm/Tf` 操作符 → 按坐标聚合成行 → 还要处理 CID 字体的
   `ToUnicode` CMap 才能把中文字形映射回 Unicode。
   这套东西的代码量**比课晓目前整个导入模块还大**，而且对"不同教务厂商导出的
   PDF 写法不同"极其脆弱 —— 一个字的坐标偏了半格，整行就串位。

2. **收益层面**（更关键）：**就算还原成功了，拿到的信息量和"粘贴纯文本"一模一样。**
   本校课表的源格式本身就是"每天一列、一门课固定四行"的课块流，
   PDF 只是把它排版成纸面好看的样式，**里面同样没有可用的列结构**。
   花大力气解出来的东西，喂给解析器还是 §3.1 那个丢星期的烂输入。

**结论**：PDF 是"用更高的成本换回同样差的数据"，直接排除。

#### 真正的出路：同一份数据，换个形态去拿

教务处官网的那份 `.xlsx`（§3.5 ③）是教务处**自己从教务系统正式导出**的，
结构完整（星期是独立的列、节次是独立的行）、**公开挂在你不用登录的地方**、
下载它不需要任何绕安全机制的操作。

**同一份数据，一个形态是死的（网页复制），一个形态是活的（官网附件）——
去拿活的那个。** 这条已经实现在 App 里，见 §7.1。

## 4. 解析器怎么工作（`service/TextImportService.ets`）

### 4.1 先判断形态

```
有 ≥2 行含制表符            → ① 制表符表格（Excel / 教务网页）
否则有 ≥3 个「周X」的行      → ② 空格分隔的表格
否则                        → ③ 一行一门课的列表
```

### 4.2 表格解析最难的一点：格子里的换行

教务系统课表的一个格子里，课程名 / 周次 / 教师 / 教室常是**四行**。
复制成纯文本之后，这些换行和"行与行之间的换行"长得**一模一样**：

```
节次	星期一	星期二
1-2	高等数学
张三
A101		大学英语
李四
B202
```

判据是：**制表符负责换列，换行是否换"记录"取决于当前在第几列。**

- 停在**最后一列**时遇到换行 → 一条记录结束
- 停在**中途**遇到换行 → 这个格子还没写完，换行留在格子里

再用一次「首列能不能解析成节次」兜底修补：首列不是节次的行，接回上一行的最后一格。

### 4.3 单元格内容拆解

```
单元格文本 → 按换行/竖线/空格切成若干段
          → 认周次段（含「周」字，或单元格场景下的裸区间 1-16）
          → 第一段是课程名
          → 从"信息段"（去掉周次后剩下的那部分）里认节次 / 教室 / 教师
```

**为什么要专门分出"信息段"**：教务系统通常把一门课写成

```
课程名 / 课程号 / 「(1~12周) (第一节-第二节) 金海 4309  阙程晟」 / 选课班级
```

也就是**周次那一行同时带着节次、校区、教室、教师**。优先用这一行拆解 ——
课程号那一行是纯数字（`12750`），让它参与只会和教室更容易混淆。

**教室 / 教师怎么认（这里踩过坑）**：

```
金海 4309  阙程晟     ← 校区 教室 教师，用空格挤在一行
```

最开始按"顺序扫，第一个像人名的就是教师"来判 —— 结果 **校区名「金海」正好是两个字，
被当成了教师**，教室也被整行吃掉。

现在的顺序是：

1. **从后往前**找第一个像人名的词 → 教师（`阙程晟`）；
2. 再看它**前一个词**是不是教室（`4309`）→ 命中就是教室；
3. 没命中的话，再找第一个**编号型**词（`4309` / `12-713` / `A101`）当教室；
4. 再不行才用「末段兜底当教室」。

教室/教师特征：

- 教室：含「楼/馆/室/区/场/房」，或「教」开头带数字，或 `A101` / `B-203` / `302`，
  或 `12-713`（**房间号必须 3~4 位** —— 放宽到 1~4 位会把周次 `1-16` 当成教室），
  或 `机房301`（汉字+数字）。
- 教师：2~4 个汉字，或带「老师/教授/讲师」后缀。

> 还有一个真实的坑：早先的教室正则包含「号」字，结果把课程名 **「信号与系统」**
> 误判成教室。现在「号」已被移出特征集。

**节次优先用格子里写的**：跨节次的课在表格里是合并单元格，摊平成文本后行标签可能只剩
「第一节」，只有格子自己写着 `(第一节-第二节)`。所以识别到这种显式写法就用它覆盖行标签。

> ⚠️ 写这个正则时踩过一次：`第一节-第二节` 里**第一个数字后面还跟着个「节」字**，
> 写成 `数字 [-~] 数字` 是匹配不上的，中间必须允许一个可选的「节/次」。

### 4.4 一格两门课

同一格可能塞两门课（单周一门、双周一门）。判定依据是**含周次的段数**，
并且要求「段数 ≥ 周次段数 × 2」才真的切 ——
否则会把「1-8周 9-16周」这种同一门课的两段周次误判成两门课。

### 4.5 周次与节次支持的写法

周次：

| 输入 | 结果 |
|---|---|
| `1-16周` / `第1-16周` / `1~16周` | 1~16 |
| `1-16`（表格单元格里没有「周」字） | 1~16 |
| `1,3,5周` | 1、3、5 |
| `1-8,10-12周` | 1~8 与 10~12 的并集 |
| `1-16周(单)` / `2-16周（双）` | 只留单周 / 只留双周 |
| `单周`（没写范围） | 按默认学期长度铺开后筛单周 |

节次：

| 输入 | 结果 |
|---|---|
| `1-2节` / `第1-2节` | 1~2 |
| `第3节` / `3` | 3 |
| `5,6` | 5~6 |
| `一二节` / `三四节` | 1~2 / 3~4 |
| `第十一节` | 11 |

### 4.6 认不出来时的态度

**宽容优先。** 解析器宁可多认一点、把不确定的地方写进告警交给用户判断，也不轻易丢掉整条记录：

- 缺周次 → 先按「1~16 周」填上，并明确告诉用户"这是我替你填的"
- 某一格认不出 → 跳过那一条，计入「有 N 处内容没认出来」
- 整段完全认不出 → 失败，但**要说人话**：
  - 没有星期信息 → 「这段内容里没找到『周一』这样的星期信息…」
  - 有星期没周次 → 「找到了星期，但没找到『几周』这样的上课周次…」

## 5. 完整流程：解析 → 预览校对 → 落库

```
粘贴课表文本 → 智能解析 → 预览校对 → 确认导入 → 本机数据库
                              ↑
                   手动添加 / 编辑课程
```

**为什么必须经过「预览确认」？** 自动解析一定有认错的地方。让用户先看一眼、
把不对的删掉，再确认，比导完再回去翻要友好得多。市面上做得好的课表 App 都是这个流程。

## 6. 手动添加（`service/ScheduleEditor.ets`）

导入不是万能的：漏了一门、临时调课、补录实验课，都得靠手动。

页面自始至终只有一份数据 —— `ScheduleItem[]`。不管是粘贴导入、手动加一门，
还是预览里删一条，改的都是这一份；真正落库时才还原成 `course` / `schedule_entry` 两张表。

落库前会**按课程名重新归并一次课程**。原因是：手动加课时用户输入的课程名可能和已有的一模一样
（比如补一门「高等数学」的实验课），如果每次都新建一条 `course`，库里就会出现两三条「高等数学」，
颜色、课程详情、以后的统计都会分叉。

## 7. 文件导入

「从文件导入」按**后缀分流**，支持 `.json` / `.txt` / `.csv` / `.xlsx`：

| 后缀 | 走哪条路 |
|---|---|
| `.json` | 内容以 `{` 开头 → **课晓格式 JSON**（备份恢复 / 分享用） |
| `.txt` / `.csv` | 文本解析器（§4） |
| **`.xlsx`** | **Excel 解析器**（§7.1）—— 给「教务系统禁复制」的学校准备的 |
| `.xls` | 不支持（老的二进制格式）。在 Excel 里**另存为 `.xlsx`** 即可 |

### 7.1 ★ Excel 导入（`service/XlsxService.ets`）

这是目前**门槛最低**的一条导入路，专门为"教务系统把复制封死了"的情况设计。
**已在本校数据上端到端跑通并实机验证。**

#### 用户要做的（四步，零门槛）

1. 去**教务处官网**找本学期的「各校区课表 / 各教学班课表」`.xlsx` 附件，下载（选你所在校区那份）
2. 课晓 →「导入课表」→「从文件导入」→ 格式切到 `.xlsx` → 找到并选中那个文件
3. 课晓把文件里**所有教学班**列出来 → 输入你的班号（如 `f250117`）筛出来 → 认领
4. 预览校对 → 确认导入

**全程不用复制、不用电脑、不用脚本、不用开开发者工具。**
实测本校那份文件里有 **265 个教学班**，搜索框一敲就定位到自己那个。

#### 技术上怎么做的（不引三方库）

`.xlsx` 本质是 **zip + 一堆 XML**。解压用系统自带的 `zlib`：

```typescript
zlib.decompressFile(zipPath, outDir)   // @kit.BasicServicesKit
```

两个必须注意的约束：

- **只认 `.zip` 后缀** —— 所以要把用户选的 `.xlsx` 先复制进**沙箱**并改名 `*.zip` 再解
- **只认沙箱路径** —— 文件选择器给的是 `file://` URI，得先 `fileIo` 复制进来

解压后读三个 XML 就够了：

| 文件 | 提供什么 |
|---|---|
| `xl/sharedStrings.xml` | **共享字符串表**。单元格 `t="s"` 时 `<v>` 存的是**这张表的下标**，不是文字本身 |
| `xl/workbook.xml` + `xl/_rels/workbook.xml.rels` | sheet 名 → `r:id` → 实际文件路径（**不能猜** sheet1.xml 的对应关系） |
| `xl/worksheets/sheetN.xml` | 网格本体。`r="D311"` 里的列字母按 **26 进制**换算成列号 |

#### 这个格式独有的三个坑（解析器专门处理过）

**坑 1：没有节次范围。** 教务网页上写「第一节-第二节」，xlsx 里**丢了** ——
因为源单元格是**纵向合并**的，而实测本校那份文件的 `mergeCells`
**全是横向**（`C311:D311` 这类），**没有一条跨行**。

→ 只能推断：**起始节次落在 1/3/5/7/9 的课默认占两节**（大课 = 连排两节）；
若下一节同一格已经有课，说明它只占一节。
→ 推断结果**必须在预览页用告警如实告诉用户**（"有 N 门课的节次是按连排两节推断的"），
不能默默猜。实测本校 22 条排课里 21 条走了这条推断。

**坑 2：同名课程有多个教学班。** 课程清单里「体育与健康（3）」出现 7 次，
教师分别是黄萍 / 高茗淇 / 曾祥意 / 秦海龙 / 范国强 / 朱乐青…，
按"第一个匹配"会**把教师填成别人的**。

→ 检测到同名课的教师不一致时，**教师栏留空**并告警，让用户按自己的教学班补上。
（宁可空着，也不要填错 —— 填错了用户根本看不出来。）

**坑 3：占位词混进课名。** 网格里会出现「通识教育选修课」「学生素质教育」
这类**不是课名**的占位文字。

→ 用白名单过滤，且**只在它没有周次信息时**才跳过。

#### 块头信息的列位（本校格式，供后续适配参考）

每个教学班一块，块头信息**散落在多列**（所以解析器是"扫描整行找特征"，不是"固定读第 N 列"）：

| 列 | 内容 |
|---|---|
| 第 5 列 | 小班代号（`f250117`） |
| 第 7 列 | 辅导员 |
| 第 10 列 | 人数 |
| 第 12 列 | 校区（金海 / 嘉善） |
| 第 14 列 | 学院 |
| 第 15 列 | 年级 |

课表网格：行 = 节次（C 列，`第一节`~`第十三节`，注意**「十一节」会省略「第」字**），
列 = 星期（**每天占两列**：课程名 + 教室），表头在 `D/E/G/I/K/M` 列。

#### 隐私

这份 xlsx 是**教务处公开发布**的，本身不含你的学号姓名；
但**你从里面认领出来的课表**是你的个人数据 —— 和 §8 一样，
真实课表绝不进仓库、绝不进安装包。自测用的是**完全编造**的 fixture
（`tools/selftest/fixture-xlsx.ts`：课名、教师、班号、学院全部虚构，
但**形状照抄真实文件**：列布局、块头写法、一格多课的分隔线、"十一节"这种省略写法）。

## 8. 隐私红线

- **真实课表绝不进仓库、绝不进安装包。** 随包分发的只有 `resources/rawfile/sample-schedule.json`，
  里面的课名、教师、教室、课程号**全部是编造的**。
- 课表只存在本机应用目录的数据库里，课晓不上传任何数据。
- 导入过程不需要任何账号密码，也不去访问教务系统。

## 9. 进阶：电脑侧工具（不随应用分发）

`tools/advanced/` 里放着三个**不进安装包**的工具（hvigor 只编译 `entry/src/main/`，
所以对包体大小的影响是 0 字节）：

| 文件 | 干什么 | 门槛 | 现状 |
|---|---|---|---|
| `README.md` | 反复制教务系统的取数思路、反调试排错、隐私说明 | — | 现役 |
| `kexiao-export.js` | 浏览器 Console 脚本：教务系统不让复制时，直接读 DOM 把表格捞出来打包下载 | 会开开发者工具 | 其它学校仍有效；本校因**根本选不中**，只能靠它绕 |
| `parse_schedule.py` | 早期方案：教务导出的 Word(.docx) → 课晓 JSON | 要电脑、要 Python | 降级保留 |

> **顺序提醒**：先试 §7.1 的 **Excel 导入**（下载一个文件就行），
> 再考虑 §3.5 ④ 的查看源码，最后才是这里的脚本。

`parse_schedule.py` 需要 Python 3，只用标准库，零依赖：

```bash
cd tools/advanced
python3 parse_schedule.py "我的课表.docx" -o ../../data/schedule.json
```

产物是课晓格式的 JSON，可以在应用的「导入课表 → 从文件导入」里选中它。

### 它当初解析的 Word 结构（仅供参考）

```
列:  [0] 时间段(上午/下午/晚上, 竖合并)
     [1] 节次(第一节..第十三节)
     [2..8] 星期一 … 星期日
```

每个单元格内，一门课由若干独立段落 `<w:p>` 组成，典型 4 段：

```
P0: 课程名            例如 "大学英语（3）"
P1: 课程号            例如 "EN2003"
P2: (周次) (节次) 校区 教室  教师
P3: 上课班级列表      （忽略）
```

## 11. 分享闭环怎么做

```
用户 A：教务系统 → （任一方式）→ 课晓 → 预览校对 → 确认导入
                                          │
                                          ▼
                              导出「课晓分享文本」（就是课晓 JSON）
                                          │
                                     微信/QQ 发出去
                                          │
用户 B：课晓 → 导入课表 → 粘贴 → 预览 → 确认导入
```

- 传输格式就复用**已经定义好的课晓 JSON**（`schemaVersion: 1`），不新造格式
- A 端要加的能力只有「导出」，B 端**一行代码都不用改**（粘贴框已经自动识别 `{` 开头）
- 还可以顺手压一下：JSON 里的字段名可以缩短、周次数组可以压成区间字符串，
  一段课表能压到 2~3 KB，微信/短信都发得动
