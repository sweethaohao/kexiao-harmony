# 课晓 · 时间模型与时次换算

> 版本：v1.0｜对应代码：`ets/common/SlotTimeTable.ets`、`ets/common/DateUtil.ets`、`ets/service/ScheduleService.ets`

## 1. 要解决的问题

教务课表只告诉我们「第几节」，但**"第一节"到底是几点，每个学校都不一样**。
而且课晓参考学校的作息不是简单的"每节 45 分钟"，而是：

```
上午  两节大课（每节大课 = 两节 45 分钟小课相连，小课之间不休息）
      08:00-08:45 / 08:45-09:30  ← 大课 1
      09:45-10:30 / 10:30-11:15  ← 大课 2（中间 15 分钟课间）
下午  12:40 开始，结构同上午 → 15:55 下课
晚上  17:00 开始 = 1 节大课 + 3 节零散小课
```

于是需要一套**可配置的"节次 → 时间"映射**，而且要能表达"大课包含多节小课"的嵌套结构。

## 2. 模型

### 2.1 PeriodConfig（时段参数）—— 用户真正要填的东西

| 字段 | 含义 | 课晓默认值 |
|---|---|---|
| `key` | 时段标识（morning / afternoon / evening） | — |
| `label` | 显示名 | 上午 / 下午 / 晚上 |
| `startTime` | **该时段第一节的开始时间** | 08:00 / 12:40 / 17:00 |
| `bigCourseCount` | 该时段有几节「大课」 | 2 / 2 / 1 |
| `smallPerBig` | 每节大课由几节小课相连 | 2 / 2 / 2 |
| `smallSlotMinutes` | 一节小课多少分钟 | 45 |
| `breakInBigMinutes` | 大课内部、小课之间的间隔 | 0（连着上） |
| `breakBetweenBigMinutes` | 大课与大课之间的课间 | 15 |
| `trailingSmallCount` | 时段末尾追加的零散小课数 | 0 / 0 / **3** |

### 2.2 SlotTime（算出来的每一节）

`SlotTimeTable.build(configs)` 按上面的参数**顺序推算出整张表**：节次号从 1 连续递增，跨时段不重复。

课晓默认作息生成结果（共 **13 节**，与教务课表"第一节～第十三节"完全对应）：

| 节次 | 时间 | 时段 | 说明 |
|---|---|---|---|
| 1 | 08:00-08:45 | 上午 | 大课 1 的前半 |
| 2 | 08:45-09:30 | 上午 | 大课 1 的后半（无课间） |
| 3 | 09:45-10:30 | 上午 | 大课 2（15 分钟课间后） |
| 4 | 10:30-11:15 | 上午 | **上午 11:15 下课** |
| 5 | 12:40-13:25 | 下午 | **12:40 下午第一节**（11:15–12:40 为午休） |
| 6 | 13:25-14:10 | 下午 | |
| 7 | 14:25-15:10 | 下午 | |
| 8 | 15:10-15:55 | 下午 | **下午 15:55 下课** |
| 9 | 17:00-17:45 | 晚上 | **17:00 晚课开始**（15:55–17:00 为傍晚休息） |
| 10 | 17:45-18:30 | 晚上 | **晚上第一节大课 18:30 结束** |
| 11 | 18:45-19:30 | 晚上 | 追加小课 |
| 12 | 19:45-20:30 | 晚上 | 追加小课 |
| 13 | 20:45-21:30 | 晚上 | **最后一节** |

### 2.3 需求里那 8 项「可自定义时间」如何落地

| 需求项 | 对应字段 |
|---|---|
| ① 学期第一周起始时间 | `Semester.startDate`（yyyy-MM-dd，第 1 周周一） |
| ② 每天课程排布 | `ScheduleEntry.weekday / startSlot / endSlot / weeks` |
| ③ 每天第一节课时间 | `configs[0].startTime` |
| ④ 每节课时长 | `PeriodConfig.smallSlotMinutes` |
| ⑤ 课间时长 | `breakInBigMinutes`（大课内）/ `breakBetweenBigMinutes`（大课之间） |
| ⑥ 午休 / 晚休时间 | 由相邻时段的 `startTime` 与上一时段的结束时间自然形成（11:15–12:40、15:55–17:00） |
| ⑦ 下午第一节课几点开始 | `afternoon.startTime` |
| ⑧ 晚上几点下课 | 由 `evening` 时段的参数推算得出 |

> 也就是说：**改 `DEFAULT_PERIOD_CONFIGS` 一个数组，整张 13 节课表自动重算**。
> 也可以走 `SlotTimeTable.fromSlots()` 直接写死每一节的时间（极端自定义场景）。

## 3. 换算链路：从「第 N 周 星期 X 第 Y 节」到真实时间

```
Semester.startDate（第 1 周周一）
        │
        ├─ weekOfDate(date) = floor((date − 第1周周一) / 7) + 1     ← 今天是第几周
        │
        ├─ dateOfWeekday(week, weekday) = 第1周周一 + (week−1)×7 + (weekday−1)
        │                                                            ← 第 N 周星期 X 是哪天
        │
        └─ SlotTimeTable.tryAt(slot).start / .end                    ← 第 Y 节几点到几点
                    │
                    ▼
        toDayCourse(item, date) → { start: Date, end: Date }         ← 这一节课的真实起止时间
```

有了真实起止时间，才能做「今天上完了吗」「下一节几点」以及后续的提醒/闹钟。

## 4. 今明日程的判定规则

```
今天有课 且 还没全部上完   → 展示「今天」
今天已全部上完（或今天没课）→ 往后找最近有课的一天，展示它
                                通常就是「明天」；明天也没课就继续往后，
                                最多找 14 天，避免出现空屏
```

> 用户原始需求是"全部过去就展示明天"。实现时多加了一步"继续往后找"，
> 因为周六深夜 + 周日没课时，只显示"明天"会得到一张空列表。

## 5. 已验证

`tools/selftest/` 用 Node 直接跑纯逻辑测试，**174 项断言全部通过**，其中时间相关覆盖：

- 13 节的生成结果逐节核对（含"大课内无课间""大课间 15 分钟""晚上 1 大课 + 3 小课"）
- 自定义作息（3 小课 × 40 分钟 + 5 分钟内部间隔 + 20 分钟大课间）生成正确
- 第 N 周 ↔ 真实日期双向换算、开学前/学期结束边界
- 用**示例课表**验证周次过滤：第 1 周有微积分（上）、无计算机导论实验；第 13 周反过来
- 今明日程：上午时段显示"今天"，深夜自动切到后面的课
