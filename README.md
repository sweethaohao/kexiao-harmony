## 快速开始

### 0. 首次准备：生成签名材料（克隆后必做一次）

`signature/` 里装着私钥、证书链与口令密文，**不入库**。克隆后先跑：

```bash
# 需要先在 DevEco 里启动模拟器、或连上真机（profile 要绑定设备 UDID）
bash tools/dev/gen-signature.sh
```

它会一次做好三件事：签发应用证书链与调试 profile、生成加密口令所需的密钥材料、
把口令密文回写进 `build-profile.json5`。不做这一步，hvigor 会因找不到签名材料而构建失败。

> 只想编译、不装到设备时，把 `build-profile.json5` 里的 `signingConfigs` 清空即可跳过。

### 1. 导入课表（在应用内完成）

课晓**不需要登录、也不去抓教务系统**。把课表交进来有两种方式：

**① 粘贴（教务系统能选中时最省事）**

在教务系统的课表页面上 `Ctrl+A` 全选、`Ctrl+C` 复制（或者在 Excel 里选中课表区域复制），
打开课晓的「导入课表」页，粘进粘贴框 → 点「解析」→ **在预览里核对/删掉认错的条目** → 点「确认导入」。

剪贴板里出来的都是「制表符分列 + 换行分行」的纯文本，所以这一个入口同时覆盖网页和 Excel 两种来源。

> ⚠️ 如果 `Ctrl+A` **什么也选不中**（有些教务系统会这么干），这条路对你就走不通 —— 直接看下面的 ②。

**② 从文件导入（教务处挂了公开课表的学校，先看这条）**

「导入课表 → 从文件导入」支持 `.json`（课晓格式，备份恢复用）/ `.txt` / `.csv` / **`.xlsx`**。

其中 **`.xlsx` 专门为「教务系统禁复制」的学校准备**：不少学校的**教务处官网**每学期
公开挂出「各校区课表 / 各教学班课表」的 Excel 附件。下载 → 选文件 → 课晓扫出里面
**所有教学班** → 搜你自己的班号认领 → 预览 → 确认导入。
**不用复制、不用电脑、不用脚本**，是绕开 `Ctrl+A` 失效 / 拦 F12 / 反调试最干净的一条路。

> `.xlsx` 本质是 zip + XML。课晓**不引三方库**：先用系统自带的 `zlib` 解压，
> 再自己读 `sharedStrings.xml` / `workbook.xml` / `worksheets/*.xml`。
> 实现见 `entry/src/main/ets/service/XlsxService.ets`，设计与局限见
> [`docs/04`](docs/04-课表导入方案.md) §7.1。
>
> `.xls`（老的二进制格式）不支持，在 Excel 里**另存为 `.xlsx`** 即可。

**③ 手动添加**

导入有遗漏、临时调课、补录实验课，用「导入课表 → 手动添加一门课」。

> 📄 各导入方式的取舍与解析算法细节，见 [`docs/04-课表导入方案.md`](docs/04-课表导入方案.md)。

### 2. 跑逻辑自测（不需要模拟器）

```bash
# Node 22+ 自带 TypeScript 类型擦除，无需 npm install
node tools/selftest/run.mjs
```

`run.mjs` 会把 `entry/src/main/ets` 下的纯逻辑模块搬到 `.build/` 下当 `.ts` 跑，
所以**改完逻辑可以立刻验证**，不用等编译。

### 3. 装到模拟器 / 真机

在 DevEco Studio 里点「运行」最省事。如果想在命令行里一键走完
「编译 → 本地签名 → 安装 → 启动」，用：

```bash
bash tools/dev/deploy.sh          # 首次会自动生成签名材料
bash tools/dev/deploy.sh --shot   # 顺便截一张图
```

> 命令行编译出来的 HAP 是未签名的，`hdc install` 会失败。
> `deploy.sh` 用 SDK 自带的 OpenHarmony 调试证书在**纯本地**签发应用证书链与调试
> profile（绑定本机 bundleName 与设备 UDID），不依赖华为账号登录。

## 数据与隐私

- 应用**不联网、不采集任何数据**，不上传课表，也不去访问教务系统。
- 课表完全由你自己交进来：**粘贴一段复制好的课表文本**，或**手动添加一门课**。全程不涉及任何账号密码。
- 课表只存在本机应用目录的一个数据库文件里，卸载应用时会一并删除。
- ⚠️ **真实课表属于个人数据，绝不能进仓库、更不能进安装包**：
  - 仓库里随包分发的是虚构样例 `sample-schedule.json`（课名、教师、教室、课程号**全部编造**）；
  - 真实课表请放在**工程外**，不要放进 `entry/src/main/resources/rawfile/`——那个目录会随 HAP 发给所有用户。

## 技术栈

- 平台：HarmonyOS NEXT，设备形态 **2in1 / phone / wearable**
- 语言/框架：ArkTS + ArkUI
- 存储：`relationalStore`（SQLite，4 张表 + 事务导入）+ `preferences`（作息参数、界面偏好）

## 设计原则

- **可推广优先**：导入入口要普通学生能用得了 —— 不要求电脑、不要求跑脚本、不要求填模板、
  **也不要求用户去绕教务系统的安全机制**。
- **合规优先**：数据由用户主动提供（粘贴 / 文件 / 手动），不抓取、不读取第三方 App 数据，
  不代填账号密码，不教用户绕过教务系统的防护。
- **换个形态拿数据**：同一份课表，网页复制是死的（可被禁掉），教务处公开的 `.xlsx` 是活的。
  与其死磕复制，不如换数据来源。
- **预览后才落库**：自动解析一定会认错，宁可多一步确认，也不要把脏数据直接写进库。
  推断出来的东西（如 Excel 里缺失的节次范围）**必须在预览页如实告警**，不能默默猜。
- **逻辑与界面分层**：纯逻辑不依赖 `@ohos` 能力，因此能在电脑上直接测试（266 项断言）。
